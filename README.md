# SmartFillMonitor - 智能灌装监控上位机系统

## 项目概述

一个**面向灌装产线的C# WPF设备监控上位机原型系统**。核心目标是验证工控上位机开发的全链路：从串口通信、协议解析、数据持久化到UI界面搭建。

**这个项目让我在以下领域获得了实战级别的理解：**
- Modbus RTU 协议通信及其可靠性保障
- WPF/MVVM 架构在工控软件中的实际落地
- 多线程与异步编程在IO密集型场景下的最佳实践

> **警告：这是一个用于学习和概念验证的个人项目，请勿部署到任何真实生产环境。**

## 我解决了哪些具体的技术难点

### 1. 串口通信的可靠性工程

在对Modbus RTU设备的轮询中，我专门设计了一套机制来应对工业现场的不稳定通信：

-   **通信失败自愈：** 实现了`连续3次读取失败`判定为断线的逻辑，自动通知UI标记断线状态，同时后台持续监听；通信恢复后自动同步连接状态，无需人工干预。
-   **数据帧同步：** 针对条码读取，设计了`遇0终止 + 高低字节ASCII拼接`的解析策略，并对读到的数据进行空值保护，防止单个传感器数据异常影响整个系统的主体数据刷新。
-   **并发控制：** 使用 `SemaphoreSlim` 精确控制串口的互斥访问，避免在多线程高频轮询下因并发读写导致的数据错乱或IO异常。

### 2. 报警生命周期的状态机管理

-   **防重复触发：** 在触发新报警前，会遍历当前活跃报警列表，通过比对`报警码`和`激活状态`来阻止同类型报警的重复插入。
-   **完整生命周期追踪：** 精确记录报警的`触发时间`、`人工确认时间`、`恢复时间`，并自动计算报警持续时长，形成完整的报警事件档案。

### 3. 配置文件的安全写入

-   **原子性守护：** 在保存串口等配置参数时，不使用简单的覆盖写，而是采用`“先写临时文件，再原子性替换”`的策略。这确保了即使在写入过程中发生意外断电或程序崩溃，原有的配置文件也不会损坏。

### 4. 确保系统“软着陆”的全局异常处理

-   **三路异常捕获：** 分别捕获`UI线程`、`非UI线程`及`未被await的Task`内部抛出的未处理异常，并记录到日志。这能防止程序遭遇不可预知的错误时直接崩溃，而是给出提示并留下可追溯的日志。

## 技术栈与架构

-   **框架与语言:** C#, .NET 8.0, WPF
-   **架构模式:** MVVM
-   **核心依赖库:**
    -   **MVVM:** `CommunityToolkit.Mvvm`
    -   **UI组件:** `HandyControl`, `LiveCharts.Wpf`
    -   **数据库:** `SQLite`, `FreeSql`
    -   **通信:** `NModbus4`, `System.IO.Ports`
    -   **日志:** `Serilog`
    -   **工具:** `CsvHelper`

**项目采用分层架构，职责分离清晰：**

*   `Models`: 数据结构与实体定义。
*   `ViewModels`: UI逻辑、状态管理与命令绑定。
*   `Views`: XAML描述的纯UI界面。
*   `Services`: 核心业务服务，如`PlcService`（通信）、`AlarmService`（报警）、`DataService`（数据）。
*   `Converters`: WPF值转换器。
*   `UserControls`: 可复用的自定义UI控件。
